# CMS Data Quality & Ingestion Pipeline — Logging Layer Documentation

## Documentation Contract

This README defines the deterministic logging rules for the CMS ingestion
pipeline. It explains how Fluent Bit provides reproducible log ingestion,
enrichment, routing, and storage across all deployment environments.

### Determinism Guarantees

- stable log formats  
- stable enrichment fields  
- stable routing behavior  
- reproducible timestamps  
- reproducible log retention  

### Side Effects

- forwards logs  
- enriches logs with provenance metadata  
- stores logs in deterministic directories  

---

## Overview

The logging layer ensures that pipeline logs are:

- deterministic  
- reproducible  
- provenance-aware  
- environment-agnostic  

Fluent Bit acts as the log router and enrichment engine.

---

## Log Sources

Pipeline logs originate from:

```code
/app/logs/*.log
```

These logs are generated by:

- Stage 01 ingestion  
- Stage 02 normalization  
- Stage 03 validation  
- Stage 04 reporting  
- Stage 05 manifest + artifact registry generation  

---

## Log Enrichment (Deterministic)

Fluent Bit adds deterministic metadata:

- `provenance.environment`  
- `provenance.executor`  
- `pipeline.version`  

These fields ensure logs can be traced across:

- local development  
- docker-compose  
- Kubernetes  
- Helm  
- cloud deployment  

---

## Log Routing

Default routing:

- **stdout** for local + docker-compose  
- **file** for deterministic artifact storage  
- **cloud sinks** (future) for production  

Routing is deterministic and pinned.

---

## Reproducibility Contract

The logging layer **must**:

- use pinned Fluent Bit version  
- use pinned parsing rules  
- use pinned enrichment fields  
- avoid nondeterministic timestamps  
- avoid nondeterministic routing  

This ensures logs behave identically across all environments.
